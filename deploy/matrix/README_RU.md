# «Только мы»: собственный сервер Matrix (подготовка)

**Статус: шаблон создан, на сервере НЕ установлен и НЕ запущен.** Существующий сайт «ТЯНЕТ» не меняется.

Цель первого этапа — закрытый тест: личные сообщения и медиа между двумя телефонами. После проверки будем добавлять участников по приглашениям, звонки, расширенное хранилище и платные функции. Все встроенные возможности клиента Element X сохраняем, экспериментальные оставляем выключенными до тестов.

## Что входит

- `compose.yaml` — контейнеры Synapse 1.163.0 и PostgreSQL 17. Снаружи слушает только `127.0.0.1:18008`, поэтому напрямую из интернета недоступен.
- `setup.sh` — локально на VPS генерирует секреты и подписывающий ключ. Если конфигурация уже существует, **не перезаписывает** её. Ничего не запускает.
- `nginx-location.conf.example` — только фрагмент для отдельного HTTPS-сайта `matrix.tyanet.ru`, не конфигурация всего Nginx.
- `.gitignore` — запрещает случайно добавить пароли, файлы пользователей и базы данных в Git.

## До установки: обязательная проверка сервера

1. Выбрать VPS и проверить ресурсы: Matrix + PostgreSQL потребляют RAM/диск; для будущего публичного сервиса понадобится отдельный расчёт нагрузки.
2. Проверить, что выбранное DNS-имя `matrix.tyanet.ru` будет указывать на **нужный** VPS. Это пока только предложенный адрес, DNS не менялся.
3. Узнать, как на VPS сейчас настроен HTTPS (Nginx, Caddy или другая программа) и какие процессы уже занимают 80/443 и 18008. **Не останавливать** текущие сервисы.
4. Настроить отдельный сертификат HTTPS и виртуальный хост `matrix.tyanet.ru` на имеющемся прокси, не трогая конфигурации сайта «ТЯНЕТ», VPN или других приложений.
5. Убедиться, что Docker Engine, Compose plugin и OpenSSL установлены. `setup.sh` должен быть прочитан и проверен перед исполнением.

Безопасные команды первичной проверки по SSH (ничего не устанавливают и не изменяют):

```bash
hostname
free -h
df -h /
docker --version
docker compose version
sudo ss -ltnp | grep -E ':(80|443|8448|18008)\b' || true
```

Скриншоты этих результатов помогут выбрать правильный способ запуска. **Не отправляйте** пароли, SSH-ключи, содержимое `.env` или `homeserver.yaml`.

## Установка ПОСЛЕ проверки VPS и HTTPS

Репозиторий можно открыть/клонировать со смартфона. На сервере достаточно этой папки `deploy/matrix`, но запускать её следует только на контролируемом VPS:

```bash
cd deploy/matrix
sudo bash setup.sh matrix.tyanet.ru
sudo docker compose config --quiet
sudo docker compose up -d
sudo docker compose ps
curl -fsS http://127.0.0.1:18008/_matrix/client/versions
```

Файлы с секретами появляются только на самом VPS. Не копируйте конфигурацию с секретами в публичный репозиторий.

Прокси должен передавать запросы `/_matrix` и `/_synapse/client` на `http://127.0.0.1:18008` и заголовки `X-Forwarded-For`/`X-Forwarded-Proto`. Пример фрагмента — в `nginx-location.conf.example`. Если 443 уже принадлежит другому сервису, конфигурацию нельзя применять без анализа: запуск может нарушить работу сайта или VPN.

После настройки DNS, HTTPS и Nginx с телефона проверяем:

```bash
curl -fsS https://matrix.tyanet.ru/_matrix/client/versions
```

## Создание аккаунтов — только владельцем сервера

Открытая регистрация и гостевой доступ отключены. Создаём тестовые аккаунты вручную, внутри контейнера:

```bash
cd deploy/matrix
sudo docker compose exec synapse register_new_matrix_user -c /data/homeserver.yaml http://localhost:8008
```

Команда запросит имя, пароль и административные права. **Не давайте участникам административные права.** Для теста достаточно двух обычных аккаунтов. При необходимости добавляйте других участников вручную; «Личное» в самом Android-приложении будет отдельным закрытым разделом, его нужно будет реализовать позднее.

В «Только мы» после публикации сервера выбираем **Войти → Другой сервер** (формулировка может отличаться) и адрес `https://matrix.tyanet.ru`. Сначала проверяем вход, переписку и получение медиа на двух смартфонах. Не создавайте аккаунт на matrix.org ради этого теста.

## Эксплуатация и безопасность

- Адрес и ключ подписи Matrix должны оставаться стабильными: перенос домена и утеря ключа могут ломать идентичность сервера.
- После установки обязательны резервные копии PostgreSQL, директории `synapse-data` (в том числе ключей подписи) и периодическая проверка восстановления. Храните копии за пределами VPS в зашифрованном виде.
- Серверный backup — не замена резервным копиям пользовательских ключей сквозного шифрования. Настройку восстановления E2EE необходимо испытать отдельно.
- Внешние push-уведомления, TURN для звонков, лимиты файлов, регистрация с приглашениями, мониторинг, антиспам и юридические условия публичного запуска ещё не настроены.
- Для будущих платных тарифов придётся разработать отдельный безопасный биллинг. Сам Synapse автоматически не обеспечивает Premium-подписки.
- Использование модифицированного Element X регулируется AGPL либо коммерческой лицензией. Перед монетизацией проверить условия распространения исходников и брендинга.
